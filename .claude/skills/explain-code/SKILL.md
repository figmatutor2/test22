# explain-code — 초보자를 위한 설명 주석 달기

지정된 코드 파일에, 코딩을 거의 모르는 사람(디자이너·기획자·입문자)이 읽어도 "이 파일이 무슨 일을 하는지" 따라갈 수 있는 설명 주석을 단다. 산출물은 주석이 추가된 원본 파일 그 자체다.

가장 중요한 약속 두 가지:

1. **코드는 건드리지 않는다.** 독자는 코드를 검증할 능력이 없으므로, 주석을 달다가 동작이 바뀌면 아무도 알아채지 못한다. 그래서 주석은 항상 "새 줄"로만 추가하고, 끝나면 스크립트로 검증한다.
2. **확인한 것만 쓴다.** 초보자는 주석을 그대로 믿는다. 틀린 주석은 주석이 없는 것보다 해롭다. 추측이 필요하면 관련 파일을 열어 확인하고, 그래도 모르면 모른다고 쓴다.

## 진행 순서

### 1. 대상 파일 확인

- 파일이 지정되지 않았으면 어떤 파일인지 먼저 묻는다.
- 여러 파일이 지정되면 한 번에 하나씩 아래 과정을 끝까지 마친 뒤 다음 파일로 넘어간다.
- 주석 문법이 없는 파일(`.json`, lock 파일, 이미지 등)은 수정하지 않는다. 대신 대화창에서 설명해 주겠다고 안내한다.
- 파일 전체를 끝까지 읽는다. 일부만 읽고 달면 뒤쪽 코드와 어긋나는 설명이 생긴다.

### 2. 백업

수정 전에 원본을 임시 폴더에 복사해 둔다. 검증에 쓰이고, git에 커밋되지 않은 파일도 되돌릴 수 있게 해 준다.

```bash
BACKUP_DIR=$(mktemp -d) && cp "<대상 파일>" "$BACKUP_DIR/" && echo "$BACKUP_DIR"
```

### 3. 코드 이해

주석을 쓰기 전에 다음을 스스로 답할 수 있어야 한다.

- 이 파일은 전체 프로그램에서 어떤 역할인가? (화면을 그리는가, 데이터를 계산하는가, 설정인가)
- 위에서 아래로 어떤 덩어리들로 나뉘는가?
- 초보자가 막힐 지점은 어디인가? (낯선 문법, 정규식, 삼항 연산자 중첩, 비동기, 훅 등)

이름만 보고 짐작되는 부분(import한 함수, 클래스명이 가리키는 스타일 등)은 해당 파일을 열어 확인한 뒤에 설명한다.

### 4. 주석 작성

세 층으로 단다.

**① 파일 상단 요약** — 파일을 열자마자 "아, 이런 파일이구나"를 알 수 있게.

```tsx
/**
 * 📌 이 파일은: 요금제 고르기부터 신청 완료까지, 앱의 모든 화면을 담고 있는 파일이에요.
 *
 * 큰 흐름
 *  1. 요금제 목록 데이터를 준비해요
 *  2. 버튼·카드 같은 작은 부품을 만들어요
 *  3. 부품을 조립해 화면 4개를 만들어요
 *  4. 주소에 맞는 화면을 골라 보여줘요
 *
 * 처음 보는 용어
 *  - 컴포넌트: 화면을 이루는 레고 블록이에요. 버튼 하나도, 화면 전체도 컴포넌트예요.
 *  - props: 컴포넌트에 건네주는 재료예요. 같은 버튼이라도 글자를 다르게 넣을 수 있어요.
 */
```

"큰 흐름"은 파일이 짧으면(대략 30줄 이하) 생략한다. "처음 보는 용어"에는 이 파일에 여러 번 나오는 핵심 용어 3~6개만 넣는다.

**② 블록 설명** — 함수, 컴포넌트, 타입, 데이터 묶음, CSS 규칙 묶음 등 의미 단위마다 바로 위에 1~3줄. "무엇을 하는지"와 "왜 필요한지"를 쓴다.

```tsx
// 전화번호 입력을 다듬는 함수예요.
// 사용자가 무엇을 치든 숫자만 남기고, 010-1234-5678 모양으로 하이픈을 넣어줘요.
function handlePhone(value: string) {
```

**③ 어려운 줄 설명** — 초보자가 혼자서는 해독할 수 없는 줄에만 바로 위에 한 줄. `setLoading(true)`처럼 이름만 읽어도 뜻이 통하는 줄에는 달지 않는다. 모든 줄에 주석이 달리면 정작 중요한 설명이 묻힌다.

```tsx
// \D는 "숫자가 아닌 글자"라는 뜻이에요. 숫자가 아닌 건 전부 지우고, 앞에서 11자리만 남겨요.
const digits = value.replace(/\D/g, "").slice(0, 11);
```

### 글쓰기 원칙

- **한국어, "~해요"체**로 쓴다. 옆자리 동료가 설명해 주는 말투.
- **코드를 한국어로 번역하지 말고 의도를 설명한다.** `// price를 문자열로 바꿔 반환해요` (✗) → `// 85000 같은 숫자를 "85,000원" 모양의 글자로 바꿔줘요` (✓). 실제 값 예시를 들면 훨씬 쉽게 읽힌다.
- **전문 용어는 처음 나올 때 한 번만 풀어 쓴다.** 상단 "처음 보는 용어"에 넣었거나 앞에서 이미 풀이한 용어는 다시 풀지 않는다. 같은 풀이가 반복되면 파일만 길어진다.
- **비유는 정확할 때만 쓴다.** 좋은 비유(컴포넌트 = 레고 블록)는 도움이 되지만, 억지 비유는 오히려 오해를 만든다.
- **반복되는 비슷한 블록은 첫 번째에서 패턴을 설명**하고, 나머지는 한 줄로 차이점만 적거나 생략한다. (예: 글자 크기만 다른 CSS 클래스 14개)
- **기존 주석은 지우거나 고치지 않는다.** 기존 주석이 이미 충분히 쉬우면 그대로 두고, 어려우면 그 위에 쉬운 설명을 덧붙인다. 이 스킬로 이미 주석을 단 파일을 다시 요청받으면 중복으로 달지 말고 부족한 곳만 보충한다.
- 이모지는 상단 요약의 📌 하나만 쓴다.

### 코드를 깨뜨리지 않는 규칙

주석은 **항상 독립된 새 줄**로, 설명하려는 코드 바로 위에, 같은 들여쓰기로 넣는다. 기존 줄의 끝에 붙이지 않는다. 기존 줄을 건드리지 않아야 5단계 검증이 "추가된 줄만 있다"는 사실로 안전을 증명할 수 있다.

위치에 따라 주석 문법이 달라지는 곳을 조심한다.

| 위치                                    | 쓸 문법           | 주의                                             |
| --------------------------------------- | ----------------- | ------------------------------------------------ |
| JS/TS 일반 코드                         | `//` 또는 `/* */` |                                                  |
| JSX 태그 **사이**(자식 자리)            | `{/* 설명 */}`    | 여기에 `//`를 쓰면 화면에 글자로 그대로 출력된다 |
| JSX 태그의 **속성 목록 안**             | `{/* */}` 불가    | 속성 사이에 넣지 말고 태그 위로 올려서 단다      |
| `return (` 또는 `? (` · `: (` · `&& (` 바로 다음 줄의 태그 위 | `//` | 괄호 안은 아직 JSX 자식 자리가 아니라 일반 코드 자리다. 여기에 `{/* */}`를 쓰면 문법 오류가 난다 |
| CSS                                     | `/* */`           | `//`는 CSS 주석이 아니다                         |
| HTML                                    | `<!-- -->`        |                                                  |
| Python·Shell·YAML                       | `#`               |                                                  |
| 문자열·템플릿 리터럴(`` `...` ``) 내부  | 넣지 않는다       | 주석이 아니라 내용이 되어 버린다                 |

그 밖에:

- 첫 줄이 특별한 의미를 갖는 파일(`#!/usr/bin/env`, `@charset`, `<!DOCTYPE>`, YAML frontmatter `---`)은 그 줄 **다음**에 상단 요약을 넣는다.
- 한 문장이 여러 줄에 걸쳐 있을 때(체이닝, 삼항 연산자, 긴 인자 목록)는 중간에 끼워 넣지 말고 문장 시작 위에 모아서 단다.

### 5. 검증

수정 후 반드시 실행한다.

```bash
python3 <이 스킬 폴더>/scripts/verify_comments_only.py "$BACKUP_DIR/<파일명>" "<대상 파일>"
```

- `OK`가 나오면 통과. 원본의 모든 줄이 순서대로 그대로 남아 있고, 추가된 줄이 전부 주석이라는 뜻이다.
- `FAIL`이면 기존 코드 줄이 바뀌었거나 사라진 것이다. 출력된 줄을 원본대로 되돌리고 다시 검증한다.
- `WARN`은 주석처럼 보이지 않는 추가 줄이 있다는 뜻이다. 출력된 줄을 직접 보고 주석이 맞는지 확인한다(여러 줄 주석의 가운데 줄 등은 정상일 수 있다).

저장할 때 자동 포매터(Prettier 등)가 돌아 기존 코드 줄의 모양을 바꾸면 `FAIL`이 날 수 있다. 이 경우 주석 때문에 코드가 바뀐 것이 아니므로, 포매터가 바꾼 줄이라는 사실을 확인하고 사용자에게 알린다.

프로젝트에 타입 검사나 빌드 명령이 있고 가볍게 돌릴 수 있으면 함께 돌려 문법이 깨지지 않았는지 확인한다. 단, 주석을 달기 전부터 있던 오류와 구분해서 보고한다.

### 6. 결과 보고

짧게 보고한다.

```
✅ <파일 경로>에 설명 주석을 달았어요.

- 상단 요약 1개, 블록 설명 N개, 어려운 줄 설명 N개
- 검증: 코드 변경 없음 확인 (추가된 줄은 모두 주석)
- 백업: <백업 경로> (임시 폴더라 컴퓨터를 재시작하면 사라질 수 있어요)

읽는 순서 추천: <어디부터 읽으면 좋은지 1~2줄>
```

주석을 달다가 버그나 문법 오류로 보이는 곳을 발견해도 **고치지 않는다.** 이 스킬의 범위는 주석뿐이다. 대신 보고 끝에 "발견한 점"으로 위치와 내용을 알려 사용자가 결정하게 한다. 코드에 거짓말하는 주석(예: 동작하지 않는 코드를 동작한다고 설명)을 달지 않도록, 그런 곳의 주석은 코드가 "하려는 일"로 표현한다.
