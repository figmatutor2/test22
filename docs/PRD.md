# PRD.md — 요금제 추천·구독 서비스

색·글자·간격·컴포넌트 같은 비주얼 규칙은 이 문서에 쓰지 않는다. 모든 비주얼 규칙은 **Design.md를 따른다.**

---

## 1. 목적

### 한 줄 정의

요금제 추천·구독은 **월말 전에 데이터가 떨어지는 고객**이 **데이터량·속도 제한 여부·실제 월 납부액을 비교해 맞는 요금제를 골라** **통신사 모바일 웹을 벗어나지 않고 바로 신청**하는 모바일 웹 서비스다.

### 해결할 문제

1. 출퇴근길에 영상을 보는 고객은 매달 20일쯤 데이터가 다 떨어진다.
2. 고객은 통신사 앱·홈페이지의 요금제 페이지를 먼저 열지만, 20개가 넘는 요금제 목록에서 몇 개만 눌러보다가 포털 검색("데이터 무제한 요금제 추천")이나 커뮤니티 후기로 이탈하고, 정보가 너무 많아 결국 변경을 포기한다.
3. 고객은 두 가지를 판단하지 못한다.
   - "무제한"이라는 이름만으로는 기본 데이터 소진 후 속도가 제한되는 요금제인지, 속도 제한이 없는 요금제인지 구분할 수 없다. ("무제한이라면서 왜 느려져요?")
   - 정가·할인가·프로모션가가 함께 표시되어 매달 실제로 내는 금액과 24개월 할인 종료 후 금액을 알 수 없다. ("그래서 제가 매달 실제로 내는 돈이 얼마예요?")

---

## 2. 대상 사용자

### 유저 스토리

- **US1.** 출퇴근길에 영상을 보는 고객으로서, 월말까지 데이터를 쓰기 위해 데이터량을 기준으로 요금제를 비교하고 싶다.
- **US2.** 20개가 넘는 요금제 앞에서 선택이 어려운 고객으로서, 비교할 후보를 줄이기 위해 내 상황에 맞는 요금제만 추려 보고 싶다.
- **US3.** "무제한" 요금제를 보는 고객으로서, 월말에 속도가 느려지지 않기 위해 기본 데이터 소진 후 속도 제한이 있는지 확인하고 싶다.
- **US4.** 여러 가격이 함께 적힌 요금제를 보는 고객으로서, 실제 부담을 알기 위해 매달 내는 금액과 24개월 할인 종료 후 금액을 확인하고 싶다.
- **US5.** 요금제를 고른 고객으로서, 포털이나 커뮤니티로 나가지 않고 요금제를 바꾸기 위해 이 서비스 안에서 바로 신청하고 싶다.

### 사용자 상황 (도메인 스토리 요약)

출퇴근길에 영상을 보는 고객 A는 이번 달에도 20일쯤 데이터가 다 떨어졌다. A는 통신사 앱의 요금제 페이지를 열었지만 20개가 넘는 요금제 중 몇 개만 눌러보았다. "무제한" 요금제가 소진 후 속도 제한이 있는지 이름만으로 알 수 없었고, 정가·할인가·프로모션가가 함께 적혀 있어 매달 내는 금액과 24개월 할인 종료 후 금액도 알 수 없었다. A는 포털 검색과 커뮤니티 후기를 찾아보았지만 정보가 너무 많아 요금제 변경을 포기했다.

## 3. 화면 목록

지켜야 할 것: ① 화면 4개(3~6개 범위) ② "신청(저장)" 흐름 1개 포함(구독 신청 → 신청 완료) ③ 샘플 라이브러리 컴포넌트와 토큰으로만 구성(Design.md를 따른다)

### 화면 구조

| 순서 | 화면 이름   | 라우트        | 한 줄 역할                                                                                        | 해결하는 유저 스토리 |
| ---- | ----------- | ------------- | ------------------------------------------------------------------------------------------------- | -------------------- |
| 1    | 요금제 목록 | `/plans`      | 요금제별 데이터량·소진 후 속도·매달 내는 금액을 한 카드에 표시해 후보를 고르게 한다               | US1, US2, US3, US4   |
| 2    | 요금제 상세 | `/plans/[id]` | 선택한 요금제의 매달 내는 금액, 할인 종료 후 금액, 소진 후 속도를 확인하고 신청으로 넘어가게 한다 | US1, US3, US4, US5   |
| 3    | 구독 신청   | `/apply`      | 신청 정보를 입력받아 구독 신청을 저장한다                                                         | US4, US5             |
| 4    | 신청 완료   | `/complete`   | 저장된 신청 내역을 표시한다                                                                       | US5                  |

### 주요 흐름

```
요금제 목록 (/plans) → 요금제 상세 (/plans/[id]) → 구독 신청 (/apply) → 신청 완료 (/complete)
```

되돌아가는 흐름:

- 요금제 상세 → 뒤로(icon/arrowLeft) → 요금제 목록 (`/plans`)
- 구독 신청 → 뒤로(icon/arrowLeft) → 요금제 상세 (`/plans/[id]`). 흐름도의 '취소'는 뒤로 아이콘과 같은 동작이다.
- 신청 완료 → 뒤로(icon/arrowLeft) → 요금제 목록 (`/plans`). 입력값이 채워진 구독 신청 화면으로 돌아가지 않는다.
- 신청 완료 → '요금제 더 보기' → 요금제 목록 (`/plans`)

## 4. 화면별 기능

### 4-1. 요금제 목록 (`/plans`)

필수 기능:

1. **헤더 (Header + Logo)**
   - 표시 항목: 화면 제목 "요금제 목록", U+ 로고
2. **요금제 카드 (Card/Plan)** — US1, US3, US4
   - 표시 항목: 요금제 이름 · 기본 데이터량 · 소진 후 속도("소진 후 ○Mbps로 제한" 또는 "속도 제한 없음") · 매달 내는 금액 1개 · 할인 종료 후 금액("25개월째부터 ○원") · '자세히' 버튼
   - Card/Plan 속성 매핑: Name = 요금제 이름, Desc = 기본 데이터량 · 소진 후 속도, Price = 매달 내는 금액, Original = 할인 종료 후 금액("25개월째부터 ○원", p03만), Discount = 사용하지 않는다(비운다), Badge = 추천 Tag(p02만 켠다), Promo = "24개월 할인" Chip(p03만 켠다). Sale Boolean이 켜고 끄는 요소는 Figma 컴포넌트에서 **확인 필요**
   - 기본 상태: 요금제 데이터(아래 표)의 p01~p04 4개 카드를 모두 표시한다. 기본 정렬은 매달 내는 금액이 낮은 순(p01 → p02 → p03 → p04)이다. 정렬 기준 문구는 화면에 표시하지 않는다.
   - 할인이 없는 요금제는 할인 종료 후 금액 줄을 표시하지 않는다.
   - 정가·할인가·프로모션가를 한 카드에 나란히 표시하지 않는다.
3. **요금제 필터 (FilterChip)** — US2
   - 표시 항목: 필터 칩 3개(단일 선택)
     - '전체': p01~p04 4개 카드 모두
     - '50GB 이상': 기본 데이터량이 50GB 이상이거나 무제한인 요금제(p02, p03, p04)
     - '속도 제한 없음': 소진 후 속도 제한이 없는 요금제(p04)
   - 기본 상태: '전체' 칩이 선택되어 있고 4개 카드가 모두 표시된다.
   - 동작: 칩을 누르면 조건에 맞는 카드만 남고, 선택한 칩이 선택 상태로 바뀐다. '전체'를 누르면 4개 카드로 돌아간다. 세 칩 모두 결과가 1개 이상이므로 필터 결과 0건 상태는 발생하지 않는다.
4. **추천 표시 (Tag)** — US2
   - 표시 항목: 추천 Tag
   - 기본 상태: p02 데일리 50GB 카드 1개에만 표시한다. 근거: US1 고객(출퇴근길 영상, 월말까지 데이터)에 맞는 요금제이기 때문이다.
5. **할인 프로모션 표시 (Chip)** — US4
   - 표시 항목: "24개월 할인" 문구
   - 기본 상태: 24개월 할인이 있는 요금제 카드에만 표시한다.
6. **상세 이동 ('자세히' Button)** — US5
   - 동작: 누르면 해당 요금제의 요금제 상세(`/plans/[id]`)로 이동한다.

로딩·빈·에러 상태: 필터 결과 0건은 위 칩 구성상 발생하지 않는다. 로딩·빈·에러 화면은 이번 범위 밖이다(6장).

### 4-2. 요금제 상세 (`/plans/[id]`)

필수 기능:

1. **헤더 (Header + icon/arrowLeft)**
   - 표시 항목: 요금제 이름, 뒤로 아이콘
   - 동작: 뒤로 아이콘을 누르면 요금제 목록(`/plans`)으로 이동한다.
2. **월 요금 (Card/Price)** — US4
   - 표시 항목: "매달 내는 금액" 1개(할인 적용 금액), 그 아래 "25개월째부터 ○원"(할인 종료 후 금액)
   - 기본 상태: 할인이 없는 요금제는 매달 내는 금액만 표시하고 할인 종료 후 줄은 표시하지 않는다.
   - 정가·할인가·프로모션가 3개를 함께 표시하지 않는다.
3. **기본 제공 항목 (List/Row)** — US1, US3
   - 표시 항목: 기본 데이터량, 소진 후 속도("소진 후 ○Mbps로 제한" 또는 "속도 제한 없음")
   - 통화·문자 등 그 밖의 행: **확인 필요**
4. **추천 표시 (Tag)**
   - 기본 상태: 목록에서 추천 Tag가 붙은 요금제일 때만 표시한다.
5. **포함 혜택 (OptionItem)**
   - 표시 항목: **확인 필요** (인터뷰에서 혜택 내용이 나오지 않음). 확정 전까지는 OptionItem 영역을 비워 둔다.
6. **신청 영역 (BottomCTA + '구독 신청하기' Button)** — US5
   - 표시 항목: 매달 내는 금액, '구독 신청하기' 버튼
   - 동작: 버튼을 누르면 선택한 요금제 id를 가지고 구독 신청(`/apply`)으로 이동한다.

잘못된 접근: ① p01~p04 외의 id로 접근하면 요금제 목록(`/plans`)으로 이동한다. 로딩·빈·에러 화면은 이번 범위 밖이다(6장).

### 4-3. 구독 신청 (`/apply`)

필수 기능:

1. **헤더 (Header + icon/arrowLeft)**
   - 표시 항목: 화면 제목 "구독 신청", 뒤로 아이콘
   - 동작: 뒤로 아이콘을 누르면 요금제 상세(`/plans/[id]`)로 이동한다. 입력값은 유지하지 않는다(다시 들어오면 빈 상태).
2. **선택한 요금제 요약 (List/Row)** — US4
   - 표시 항목: 요금제 이름, 매달 내는 금액, 할인 종료 후 금액(할인 있는 요금제만)
3. **신청 정보 입력 (Input)** — US5
   - 표시 항목: 이름 입력란, 휴대폰 번호 입력란
   - 기본 상태: 두 입력란 모두 비어 있다.
4. **개인정보 수집·이용 동의 (Checkbox)** — US5
   - 기본 상태: 체크되지 않은 상태
5. **신청하기 (BottomCTA + '신청하기' Button)** — US5
   - 기본 상태: 이름이 비어 있거나, 휴대폰 번호가 숫자 11자리가 아니거나, 동의가 체크되지 않으면 버튼이 비활성 상태다.
   - 동작: 이름이 비어 있지 않고, 휴대폰 번호가 숫자 11자리이고, 동의가 체크되면 버튼이 활성화된다. 누르면 Subscription 1건을 브라우저 저장소(localStorage)에 저장하고 신청 완료(`/complete`)로 이동한다. 서버는 없다. 중복 신청은 허용한다(본인 인증은 범위 밖).
   - 휴대폰 번호는 하이픈 없이 숫자만 입력한다.
   - 저장 실패 시: 신청 완료로 이동하지 않고 구독 신청 화면에 머문다. 입력값과 동의 체크는 유지하고, 안내 문구를 표시한다. '신청하기' 버튼은 활성 상태로 두어 다시 누르면 저장을 다시 시도한다.

잘못된 접근: ② 요금제 id 없이 `/apply`에 접근하면 요금제 목록(`/plans`)으로 이동한다.

오류 상황과 안내 문구:

| 상황                                                   | 안내 문구                                     | 표시 위치               |
| ------------------------------------------------------ | --------------------------------------------- | ----------------------- |
| 이름 입력란을 비운 채 다음 입력란으로 이동             | 이름을 입력해 주세요.                         | 이름 입력란 아래        |
| 휴대폰 번호 입력란을 벗어날 때 값이 숫자 11자리가 아님 | 휴대폰 번호 11자리를 숫자로 입력해 주세요.    | 휴대폰 번호 입력란 아래 |
| 저장 실패(브라우저 저장소에 쓰지 못한 경우)            | 신청을 저장하지 못했어요. 다시 시도해 주세요. | 신청하기 버튼 위        |

### 4-4. 신청 완료 (`/complete`)

필수 기능:

1. **완료 표시 (icon/doneMark)** — US5
   - 표시 항목: 완료 아이콘, "구독 신청이 완료됐어요" 문구
2. **신청 내역 (List/Row)** — US5
   - 표시 항목: 신청 번호, 요금제 이름, 매달 내는 금액, 신청 일시, 신청자 이름
   - 기본 상태: 방금 저장한 Subscription 값으로 채운다. 신청 일시는 `YYYY.MM.DD HH:mm` 형식으로 표시한다. 신청자 이름은 마스킹 없이 그대로 표시하고 휴대폰 번호는 표시하지 않는다.
3. **'요금제 더 보기' (BottomCTA + Button)**
   - 동작: 누르면 요금제 목록(`/plans`)으로 이동한다.
4. **헤더 (Header + icon/arrowLeft)**
   - 표시 항목: 화면 제목 "신청 완료", 뒤로 아이콘
   - 동작: 뒤로 아이콘을 누르면 요금제 목록(`/plans`)으로 이동한다.

잘못된 접근: ③ 저장된 신청이 없는 상태로 `/complete`에 접근하면(새로고침 포함) 요금제 목록(`/plans`)으로 이동한다. 로딩·빈·에러 화면은 이번 범위 밖이다(6장).

### 요금제 데이터 (실습용 가상 데이터)

인터뷰의 고객 상황(월말 전 데이터 소진, "무제한" 이름 혼동, 24개월 할인 후 금액 인상)을 재현하도록 구성했다. 실제 통신사 요금제가 아니다.

| --- | ------------- | ----------------------- | ---------- | -------------- | --------------------- | ---- | ----------------------------------------------------- |
| p01 | 슬림 10GB     | 39,000원                | 10GB       | 1Mbps로 제한   | 할인 없음             | -    | 출퇴근 영상 시청이 적은 고객용 기본 요금제            |
| p02 | 데일리 50GB   | 52,000원                | 50GB       | 1Mbps로 제한   | 할인 없음             | 추천 | 출퇴근길 영상을 월말까지 보고 싶은 고객용             |
| p03 | 무제한 라이트 | 59,000원 (24개월 할인)  | 기본 100GB | 5Mbps로 제한   | 25개월째부터 69,000원 | -    | 이름은 무제한이지만 기본 데이터 소진 후 속도가 제한됨 |
| p04 | 무제한 프리   | 75,000원                | 무제한     | 속도 제한 없음 | 할인 없음             | -    | 데이터를 다 써도 속도 제한이 없는 요금제              |

### 어기면 안 되는 것 (O/X 판정 규칙)

1. 요금제 목록의 기본 상태('전체' 칩 선택)에서 요금제 카드가 정확히 4개(p01~p04) 있다.
2. 추천 Tag는 요금제 목록의 기본 상태('전체' 칩 선택)에서 1개만 있다.
3. 요금제 카드와 요금제 상세에는 금액이 "매달 내는 금액" 1개와 "할인 종료 후 금액" 최대 1개만 있다. 정가·할인가·프로모션가 3개가 함께 표시되지 않는다.
4. 할인 종료 후 금액은 24개월 할인이 있는 요금제(p03)에만 있다.
5. 이름에 "무제한"이 들어간 요금제(p03, p04)의 카드와 상세에는 "소진 후 ○Mbps로 제한" 또는 "속도 제한 없음" 중 하나가 있다.
6. 구독 신청 화면에서 이름이 비어 있거나, 휴대폰 번호가 숫자 11자리가 아니거나, 동의가 체크되지 않으면 '신청하기' 버튼이 눌리지 않는다.
7. 신청 완료 화면의 요금제 이름과 매달 내는 금액이 구독 신청 화면에서 선택한 요금제와 같다.

```yaml
Subscription: # 구독 신청 1건
  id: string # 신청 번호. 저장 시 생성. 형식 S-YYYYMMDD-HHmmss(저장 시각 기준)

  phone: string # 휴대폰 번호. 숫자 11자리
  plan_id: string # 요금제 id (p01 | p02 | p03 | p04)
  monthly_price: number # 신청 시점의 매달 내는 금액(원)
  agreed_privacy: boolean # 개인정보 수집·이용 동의. true일 때만 저장
  created_at: datetime # 신청 일시. 저장 시 생성. 화면 표시 형식 YYYY.MM.DD HH:mm. 저장 위치는 브라우저 저장소(localStorage)

  name: string

  data: string # "10GB" | "50GB" | "기본 100GB" | "무제한"

  discount_months: number | null # 할인 기간(개월). 할인 없으면 null
```
